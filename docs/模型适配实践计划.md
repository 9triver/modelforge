# 模型适配技术实践计划

基于《分布偏移下的模型适配技术综述》的分析框架，选择典型模型与方法进行系统性实现与验证。

---

## 总体路线

```
Phase 1: 适配实现（模型 × 方法）
    ├── Part A: 表格数据 + 传统ML/MLP
    └── Part B: 图像数据 + CNN/ViT
         │
         ▼
Phase 2: 评估体系实现
    ├── 性能指标 + 校准指标
    ├── 可视化（Reliability Diagram, t-SNE, 成本-效果图）
    └── 无标签评估方法
         │
         ▼
Phase 3: Shift Detection 实现
    ├── 统计检验方法
    ├── 模型内部信号监控
    └── 诊断决策流程
         │
         ▼
Phase 4: 工具库封装
    ├── 核心 API 抽象
    ├── 实验复现脚本
    └── 文档 + 示例
```

## Phase 1: 适配实现

### Part A: 表格数据

#### 数据集（4个，典型+可获取）

| 数据集 | Shift 类型 | 域拆分 | 任务 | 规模 | 获取方式 |
|-------|-----------|-------|------|------|---------|
| ACS Income (Folktables) | Covariate Shift | 美国各州为域，如 CA→TX | 二分类(收入>50K) | ~3.2M | `pip install folktables`，自动从 Census API 拉取 |
| Gas Sensor Array Drift | 真实传感器漂移 | 按月份(batch1→batch10) | 多分类(6类气体) | 13.9K | [UCI ML Repository](https://archive.ics.uci.edu/dataset/224) 直接下载 |
| Electricity (ELEC2) | Concept Drift | 按时间窗口 | 二分类(涨跌) | 45K | `river` 库自带：`from river.datasets import Elec2` |
| sklearn 合成数据 | 可控注入任意Shift | 手动旋转/平移/重采样 | 二分类/多分类 | 自定 | `sklearn.datasets.make_classification` |

**为什么选这4个**：Folktables 是表格DA最接近标准 benchmark 的（50个真实域），Gas Sensor 是罕见的真实漂移数据，Electricity 是 Concept Drift 经典，合成数据做消融控制变量。

#### 模型（6个，典型+sklearn/xgboost直接可用）

| 模型 | 代表的族 | 获取 | 为什么选 |
|-----|---------|------|---------|
| LogisticRegression | 线性参数族 | `sklearn.linear_model` | 天然校准好，做 baseline 参照 |
| GaussianNB | 概率生成族 | `sklearn.naive_bayes` | 概率校准差的典型代表 |
| SVC (RBF kernel) | 核方法族 | `sklearn.svm` | 核函数绑定分布，适配最难 |
| RandomForestClassifier | 集成族(Bagging) | `sklearn.ensemble` | 树模型代表，支持增量(加树) |
| XGBClassifier | 集成族(Boosting) | `pip install xgboost` | 工业界主力，支持 continue training |
| MLPClassifier | 浅层神经网络 | `sklearn.neural_network` | 传统ML到DL的过渡 |

#### 适配方法（7种）

| 方法 | 类型 | 实现来源 | 代码量 |
|-----|------|---------|-------|
| Baseline (无适配) | — | — | — |
| 实例加权 (uLSIF) | 数据层 | `densratio` 包 (`pip install densratio`) | 估计密度比→传入 sample_weight |
| TCA | 特征层 | `transfertools` 包 或自实现(~100行) | 核PCA对齐→新特征上训练 |
| 全量重训 | 模型层 | sklearn/xgboost 原生 | 目标域数据直接 fit |
| XGBoost continue_training | 模型层(增量) | `xgb_model` 参数 | 续训N轮 |
| Platt Scaling | 输出层 | `sklearn.calibration.CalibratedClassifierCV` | method='sigmoid' |
| Isotonic Regression | 输出层 | 同上 | method='isotonic' |

#### 关键实验（4个核心问题）

| 编号 | 研究问题 | 实验设计 |
|-----|---------|---------|
| A1 | 不同模型族对 Covariate Shift 的鲁棒性差异 | Folktables CA→TX/NY/FL，6个模型 baseline 性能退化对比 |
| A2 | 校准 vs 重训的性价比 | 仅 Platt vs 仅重训 vs Platt+重训，Folktables 上 6个模型 |
| A3 | 实例加权对哪些模型有效 | uLSIF 加权后6个模型的提升幅度对比 |
| A4 | 漂移强度与适配策略的关系 | 合成数据，控制漂移强度(轻/中/重)，对比各策略的有效区间 |

### Part B: 图像数据

#### 数据集（4个，典型+可获取）

| 数据集 | 任务 | 域 | 规模 | 获取方式 |
|-------|------|---|------|---------|
| Office-Home | 分类(65类) | Art/Clipart/Product/Real (4域) | 15.5K | [官方链接](https://www.hemanthdv.org/officeHomeDataset.html) 或 HF: `davanstrien/office_home` |
| VisDA-2017 | 分类(12类) | Synthetic→Real | 280K | [GitHub: VisionLearningGroup/taskcv-2017-public](https://github.com/VisionLearningGroup/taskcv-2017-public) |
| Cityscapes + Foggy Cityscapes | 检测/分割 | 晴天→雾天 | 5K+5K | [cityscapes-dataset.com](https://www.cityscapes-dataset.com/) 注册下载 |
| COCO 2017 | 检测/分割 | 自构造域拆分(室内vs室外) 或作为源域→Cityscapes | 118K | [cocodataset.org](https://cocodataset.org/) 直接下载 / `fiftyone` 加载 |

**为什么选这4个**：Office-Home 是分类DA标准中等规模 benchmark，VisDA 是大规模合成→真实的标准测试，Cityscapes 覆盖分割+检测DA，COCO 是通用CV基石数据集。

#### 模型（5个，全部 HF/torchvision 可获取）

| 模型 | 代表什么 | 获取 | 预训练权重 |
|-----|---------|------|-----------|
| ResNet-50 | CNN 经典，含BN | `torchvision.models.resnet50(weights='IMAGENET1K_V2')` | ImageNet |
| ViT-B/16 | Vision Transformer | `timm.create_model('vit_base_patch16_224', pretrained=True)` 或 HF: `google/vit-base-patch16-224` | ImageNet-21K |
| CLIP ViT-B/32 | 多模态大模型 | `pip install open_clip_torch` 或 HF: `openai/clip-vit-base-patch32` | LAION/OpenAI |
| DeepLab-v2 (ResNet-101) | 分割经典 | [GitHub: kazuto1011/deeplab-pytorch](https://github.com/kazuto1011/deeplab-pytorch) | ImageNet + COCO |
| YOLOv8 | 检测现代主力 | `pip install ultralytics`，`YOLO('yolov8m.pt')` | COCO |

#### 适配方法（8种）

| 方法 | 类型 | 实现来源 |
|-----|------|---------|
| Baseline (source only) | — | 直接用预训练权重评估 |
| AdaBN | 特征层(零成本) | 自实现(~20行)：目标域前向传播更新 BN 统计量 |
| DANN | 特征层(对抗) | [GitHub: thuml/Transfer-Learning-Library](https://github.com/thuml/Transfer-Learning-Library) (`tllib`) |
| SHOT | 特征层(Source-Free) | 同上 `tllib`，或 [原作者代码](https://github.com/tim-learn/SHOT) |
| 全量微调 | 模型层 | PyTorch 原生训练 |
| LoRA | 模型层(参数高效) | `pip install peft`，HF PEFT 库 |
| CoOp | Prompt Tuning | [GitHub: KaiyangZhou/CoOp](https://github.com/KaiyangZhou/CoOp) |
| Temperature Scaling | 输出层 | 自实现(~30行)：验证集上优化 T |

#### 关键实验（5个核心问题）

| 编号 | 研究问题 | 实验设计 |
|-----|---------|---------|
| B1 | AdaBN 零成本 baseline 的有效性 | Office-Home 12个方向，AdaBN vs DANN vs 全量微调 (ResNet-50) |
| B2 | 参数高效 vs 全量微调 | Office-Home 上 LoRA(rank=4/8/16) vs 全量微调 vs 线性探测 (ViT-B/16) |
| B3 | CLIP zero-shot 能否替代传统DA | Office-Home + VisDA，CLIP zero-shot vs CoOp(4-shot) vs ResNet+DANN |
| B4 | 合成→真实的最优策略 | VisDA Syn→Real，5种方法全面对比 (ResNet-50 + ViT-B/16) |
| B5 | COCO 预训练→Cityscapes 的检测适配 | YOLOv8 COCO→Cityscapes，全量微调 vs few-shot微调(10%/50%标注) |

## Phase 2: 评估体系实现

### 2.1 性能指标模块

```python
# 目标：实现统一的评估接口
class AdaptationEvaluator:
    def evaluate(self, model, X_source, y_source, X_target, y_target):
        return {
            # 判别性能
            "accuracy": ...,
            "f1_macro": ...,
            "auc_roc": ...,
            # 校准性能
            "ece": ...,        # Expected Calibration Error
            "mce": ...,        # Maximum Calibration Error
            "brier": ...,      # Brier Score
            # 域距离
            "proxy_a_distance": ...,
            "mmd": ...,
            # 效率
            "adaptation_time_sec": ...,
            "adapted_params_ratio": ...,
        }
```

视觉任务额外指标：

```python
class VisionEvaluator(AdaptationEvaluator):
    # 分割
    "miou": ..., "dice": ..., "pixel_acc": ...,
    # 检测
    "map50": ..., "map50_95": ...,
    # 特征可视化
    "tsne_plot": ...,           # 源域/目标域特征分布
    "grad_cam": ...,            # 适配前后注意力变化
    "attention_map": ...,       # ViT attention 可视化
```

### 2.2 校准可视化

| 可视化 | 内容 | 横轴 | 纵轴 |
|-------|------|------|------|
| Reliability Diagram | 校准曲线 vs 对角线 | 预测概率 (binned) | 实际正例比例 |
| ECE Bar Chart | 各模型适配前后 ECE | 模型 | ECE值 |
| Confidence Histogram | 预测置信度分布 | 置信度 | 频次 |

### 2.3 成本-效果分析可视化

| 图表 | 横轴 | 纵轴 | 每个点 |
|-----|------|------|-------|
| Pareto 图 | 适配耗时 (log scale) | 目标域 Accuracy 提升 | 一种方法 |
| 参数效率图 | 适配参数比例 (log) | 目标域性能 | LoRA/Adapter/全量/线性 |
| 漂移强度-性能曲线 | 注入漂移强度 | 目标域 Accuracy | 不同适配方法的曲线 |
| 热力图 | 模型 (行) | 适配方法 (列) | 颜色 = 性能提升幅度 |

### 2.4 无标签评估

| 方法 | 实现思路 |
|-----|---------|
| Importance-Weighted CV | 用 uLSIF 估计密度比 → 加权验证集性能 |
| 预测置信度监控 | 适配后目标域的预测概率分布是否更"均匀"（不过度集中于0/1） |
| 多增强一致性 | 对同一样本做 K 次增强推理，计算预测一致性 |
| 邻域一致性 | 目标域特征空间中 K 近邻预测是否一致 |

## Phase 3: Shift Detection 实现

### 3.1 统计检验方法

| 方法 | 输入 | 输出 | 实现依赖 |
|-----|------|------|---------|
| PSI | 两组特征分布 | PSI值 + 特征级明细 | 自实现 |
| KS Test | 两组单变量样本 | 统计量 + p-value | scipy.stats |
| Chi-Square Test | 两组类别分布 | 统计量 + p-value | scipy.stats |
| MMD | 两组高维样本 | MMD值 + 置换检验p-value | 自实现(核函数) |
| Wasserstein Distance | 两组样本 | W-distance | scipy.stats / POT |
| Classifier Two-Sample Test | 两组样本 | 域分类器 accuracy | sklearn |

### 3.2 模型内部信号

| 模型族 | 信号 | 提取方式 |
|-------|------|---------|
| 决策树/RF | 叶节点分布 | model.apply() → 统计叶ID分布 |
| RF | OOB error | oob_score_ 属性 |
| XGBoost/LightGBM | SHAP 值分布 | shap 库 |
| LR | 系数稳定性 | 对比两个时期训练的 coef_ |
| KNN | 近邻距离分布 | kneighbors() → 距离统计 |
| CNN | BN 统计量 | 遍历 BN 层，提取 running_mean/var |
| ViT/Transformer | Attention 熵 | hook 提取 attention weights → 计算熵 |
| ViT | CLS token embedding | hook 提取 → 对比分布 |

### 3.3 Concept Drift 检测器

| 方法 | 实现复杂度 | 特点 |
|-----|-----------|------|
| DDM | 低 | 简单，仅检测突变 |
| EDDM | 低 | 对渐变更敏感 |
| ADWIN | 中 | 自适应窗口 |
| Page-Hinkley | 低 | 均值变化检测 |

### 3.4 诊断流水线

```python
class ShiftDiagnostic:
    def diagnose(self, X_source, y_source, X_target, y_target_optional=None):
        return {
            "covariate_shift": {
                "detected": True/False,
                "severity": "mild/moderate/severe",
                "evidence": {
                    "psi": {...},           # 特征级 PSI
                    "ks_tests": {...},      # 各特征 KS 检验
                    "mmd": ...,             # 整体 MMD
                    "classifier_auc": ...,  # 域分类器 AUC
                },
                "drifted_features": [...],  # 漂移最严重的特征
            },
            "label_shift": {
                "detected": True/False,
                "evidence": {...},
            },
            "concept_drift": {
                "detected": True/False,     # 需要 y_target
                "evidence": {...},
            },
            "recommended_action": "calibrate" / "reweight" / "retrain" / "domain_adapt",
        }
```

### 4.2 核心 API 设计

```python
from adapt.detection import ShiftDiagnostic
from adapt.adaptation import KMM, PlattScaling, DANN, LoRAAdapter
from adapt.evaluation import AdaptationEvaluator

# 1. 诊断
diag = ShiftDiagnostic()
report = diag.diagnose(X_source, y_source, X_target)
print(report["recommended_action"])  # → "reweight"

# 2. 适配 — 统一接口
adapter = KMM()
weights = adapter.fit_weights(X_source, X_target)
model.fit(X_source, y_source, sample_weight=weights)

# 或深度学习
adapter = DANN(backbone="resnet50", num_classes=31)
adapter.fit(source_loader, target_loader, epochs=50)

# 或 LoRA
adapter = LoRAAdapter(model=vit, rank=8)
adapter.fit(target_loader, epochs=10)

# 3. 校准
calibrator = PlattScaling()
calibrator.fit(y_val, model.predict_proba(X_val))
calibrated_probs = calibrator.transform(model.predict_proba(X_target))

# 4. 评估
evaluator = AdaptationEvaluator()
results = evaluator.evaluate(
    model, X_target, y_target,
    probs_before=probs_original,
    probs_after=calibrated_probs,
)
evaluator.plot_reliability_diagram(results)
evaluator.plot_pareto(all_experiment_results)
```

## 实施节奏

| 阶段 | 内容 | 产出 |
|-----|------|------|
| **Phase 1A** | 表格数据 + 传统ML适配 | 11个模型 × ~10种方法的结果表 |
| **Phase 1B** | 图像数据 + CNN/ViT适配 | 分类/分割/检测 DA 结果表 |
| **Phase 2** | 评估指标 + 可视化 | 校准分析、Pareto图、热力图、t-SNE |
| **Phase 3** | Shift Detection | 检测方法对比 + 诊断流水线 |
| **Phase 4** | 封装为工具库 | 可安装的 Python 包 + API 文档 |

每个 Phase 完成后都有可独立交付的实验结论和代码。Phase 之间的实现可以部分并行（比如 Phase 2 的评估模块在 Phase 1 过程中就需要逐步搭建）。
